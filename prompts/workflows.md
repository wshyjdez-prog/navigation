# 按任务选择的工作流程

每次选择与目标有关的一段；不要默认把以下所有工作一次性执行。方括号为待填写内容。

## W01：工程与环境初始化

```text
本次建立最小可运行 Linux/Qt Widgets/CMake 工程，由 1 号牵头。
先阅读 docs/development-environment.md，按已确定的 Ubuntu Desktop 24.04 LTS amd64 虚拟机、Qt 6.4.2、GCC/G++ 13.3.0、CMake 3.28.3 与 C++17 创建环境；核对仓库是否已有工程，记录真实 Qt Kit、包修订、显示和设备条件。版本不符先报告，不能换成“最新版”或虚构安装结果。
创建能演示窗口/页面切换与基本控件的最小工程，并为后续模块留下明确接口；算法、数据、定位和语音暂未接入时清楚标注 Mock。
在可用 Linux 环境配置、编译并运行，记录实测命令、依赖与证据；无法运行时说明阻塞，先完成可验证内容。输出另一位组员从全新克隆复现的步骤，以及 project.md 的精确环境记录。
```

## W02：一个模块的开发

```text
本次模块：[名称]。目标：[行为]。范围：[路径]。验收：[输入/操作/期望/异常]。
先读调用方与已有契约，说明依赖和本次边界；接口未定时提出最小契约与固定样例，让其他模块可以并行开发。
以能运行或验证的最小闭环推进实现，采用当前已确认方案；触及关键算法新选型或未决跨组接口时分别进入对应选择流程。正常业务实现不需要每改一行都征求确认。
完成必要的正确性、集成与异常验证，标清 Mock 和真实实现；更新入口、接口约定、当前状态及剩余工作，留下他人可以接入的示例。
按 AGENTS.md 第 8 节及 docs/navit-benchmark.md 核查 Navit 对应能力，在可比条件下实测并记录双方性能、质量、差异和原始证据，更新报告索引与 project.md；缺少条件或无对应能力也须保留原因、依据与补测步骤。功能实现状态和对标状态分别记录，可比项未测不能将模块整体验收标为已完成。
```

## W03：关键算法组合对比

```text
本次算法抉择：[模块/目标]。必须满足：[正确性/接口/资源约束]。
阅读已有决定；条件没变且已有确认时直接复用，否则新建 decision_log.md 记录。
第一步：给出有实质差异的候选组合，每套写清算法、结构/索引、执行方式、参数与依赖，说明预期优缺点、与已有模块关系，推荐其中 2–3 种，并提供“忽略：仅本次跳过方案对比规则”。等待我选定试验范围。
第二步：只实现所选 2–3 种，用一致契约、数据和当前环境测试；先正确性，再测耗时/样本数/内存/适用吞吐或帧率。契合度须列已有接口/回归通过数、适配改动、受影响模块、数据转换、线程/生命周期和依赖冲突。记录环境、构建模式、预热/重复次数、数据标识、命令与原始结果；失败/未测保留原因。
第三步：展示对照表和建议，等待我从入选组合中确认 1 种最终方案；全部不合格则修复或标阻塞，不宣告完成。
第四步：按本次新增文件清单清理未选组合专属代码/依赖/入口，保留共享代码和报告，不删他人工作；复验所选方案并同步 project.md、decision_log.md 及适用日志。
各入选组合及正式方案还须按 docs/navit-benchmark.md 对比 Navit 的等价任务，将报告 ID、差异与限制关联 decision_log.md；条件一致且证据可追溯时可复用同一 Navit 基线。
选择忽略时只跳过这一次多方案对比，按已明确需求继续单方案工作并记录采用方案；不跳过跨组确认、正确性验证或 Navit 对标及记录。当前环境不足不得把估测写成实测。
```

## W04：跨组接口接入与 G6 联调

```text
相关接口：[X01–X09]。对方资料：[版本/头文件/数据样例/未提供]。本次目标：[接入行为或联调用例]。
核查已有确认和真实交付；列清双方输入输出、ID/坐标/单位、错误、ABI、线程/回调生命周期、版本与构建依赖。展示可用方案及验收影响，未确认时等待选择再处理依赖部分。
以适配器隔离差异，先做契约与本地样例验证；对方不可用时可以继续 Mock，但明确尚未真实联调。
若涉及 G6，按双方真实版本在目标环境执行定位/导航/偏航/到达、计算失败和回调退出等适用用例。报告记录环境、数据、步骤、预期/实际、通过/失败数、缺陷和复测证据。没有真实对方参与或调用证据时不能标已联调。
```

## W05：排错与回归

```text
现象：[实际行为]。期望：[正确行为]。复现步骤：[步骤]。相关日志/环境：[内容]。
先复现或明确无法复现的条件，沿输入→模块→接口→结果检查证据；区分代码缺陷、协议差异和环境问题。
提出最小修复并执行，不无故重写模块或升级依赖；若修复实质改变关键算法或公共契约，说明影响并走相应选择流程。
通过能复现原问题的验证确认修复，再检查受影响接口和异常场景。输出根因、改动、前后结果和仍未验证的限制，不把“未再观察到”当作全面验证。
修复涉及性能或功能完善时，按 AGENTS.md 第 8 节重测受影响的 Navit 对标场景，记录本组修复前后与 Navit 的差异；不可比或未测时保留原因及补测事项。
```

## W06：阶段验收与交付材料

```text
本次验收：[第几次作业/具体模块]。请对照当前 Linux 任务摘录和 project.md，逐项列出要求、负责人、入口与证据、实际状态和缺口。
执行与本次变更及阶段相关的检查，不为文档或低影响改动添加无意义测试。构建、模块测试、Linux 图形运行、PAL 真实服务、跨组联调分别给出状态。
最终交付核对 Linux 可执行程序、完整 CMake 工程、运行依赖/离线数据、用户手册/设计/API/README、G6 联调报告、Linux 截图及 3–5 分钟运行视频。未提供性能阈值先确认；未实测的数据留空说明原因。
汇总所有模块的 Navit 对标报告、双方版本/环境/数据、性能和质量差异、退化与改进计划，以及未测/不适用项的依据和责任人；可比项未测不得标模块整体验收已完成，不以算法多方案试验的“一次忽略”跳过此项。
缺失材料列下一步，不生成虚构截图、视频、测试结果或个人理解反馈。按授权准备提交内容，提交/上传另以当前用户授权为准。
```

## W07：暂停、恢复与组员交接

```text
请为当前任务生成可续接记录：组员/模块/目标、已实现内容与入口、工作区未提交变更、已确认接口/方案记录、真实验证及证据、未验证部分、阻塞条件、下一项具体操作。
按实际状态更新项目文件。保留当前用户的范围和决定，不把历史其他组员的选择自动当成本人的新授权。
恢复任务时先对照实际工作区、最近记录和代码核对变化，再继续下一步；不要重新实现已完成模块，也不要从提示词中的示例推断功能存在。
```
