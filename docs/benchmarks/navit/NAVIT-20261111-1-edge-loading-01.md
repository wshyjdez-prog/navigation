## 范围与基线

功能：地图拖动/缩放时，新露出的边缘不留空白。入选组合：A 外扩帧（四周 256 px）+ 渐进发布 + z-2 粗底图；B 后台预取（当前级外一圈、z-1 全视野、z+1 中心）+ 渐进发布 + 请求延迟 60 ms。两者共用“中心优先生成、每 100 ms 发布一次”的渐进逻辑。

- 本组：`/home/abt/navigation`（非 Git 工作区，未提交），Release。环境同 `NAVIT-20261111-1-area-labels-01`：Ubuntu 24.04.5 虚拟机，8 vCPU / 9.7 GiB，Qt 6.4.2，GCC 13.3.0，offscreen 软件光栅。测量期间没有其他重负载。
- 数据：`hubei-261109.osm.pbf`（SHA256 `da2b0200…0297ab`），索引 `xyz-v4-labels2`（含面/道路名称）。
- Navit：0.5.7，`/home/abt/navit`。

## 方法

临时程序 `EdgeBench`（存档于 `NAVIT-20261111-1-edge-loading-01/evidence/EdgeBench.cpp.txt`，测完已从 CMake 删除）。武汉中心 114.305,30.593，1280×800。每轮先删除全部 PNG 瓦片（冷缓存），从 z13 和 z15 各跑一个序列：初始 → 向东平移 4 次（每次 30% 宽）→ 向北平移 2 次 → 缩小 2 次（×2）→ 放大 2 次（×0.5）。每步都等完成帧，再停 400 ms 模拟用户停顿（B 的预取在此期间运行）。每种策略 3 轮。

指标：
- 预先覆盖率：上一完成帧覆盖新视野的比例。
- 首帧延迟：从 request 到首帧的时间。
- 首帧空白：可见区内无图瓦片的比例。
- 空白消失时间：首个空白瓦片数为 0 的帧。
- 完成时间。
- 峰值 RSS：`/usr/bin/time -v` 测得。
- 中位数/P95 按最近秩计算；平移每格 n=18，缩放每格 n=6。

另外，在界面中 B 要停顿 60 ms 才发请求，A 为 180 ms。A 的外扩底图会在约 30 ms 的重绘中直接补上边缘，B 则要等请求返回。

结论（仅限本环境）：A 显著减少用户可见的空白，尤其是缩小时；代价是生成更多瓦片，完成更慢、内存更高。B 平移后完成很快，但缩小时大面积空白。最终选 A。

清理 B 后复测 A（`evidence/edge-post.csv`）：平移空白消失中位 21.1 / 25.4 ms，缩小 51.7 / 375.9 ms，完成时间与试验相差 ≤ 10%，峰值 RSS 253.8 MiB。
