# NAVIT-20261111-1-map-clarity-01

日期：2026-11-11（Asia/Shanghai）。负责人：1。状态：**部分完成**。本组三档已实测；Navit 对比为不适用加受阻。

## 范围

地图菜单新增“地图清晰度 高/中/低”。清晰度即瓦片渲染密度：低 256 px（原行为）、中 384 px（1.5×）、高 512 px（2×）。三档瓦片层级和数量不变，文字与线宽在屏幕上的大小也不变；合成时开启平滑缩放。这只给既有 XYZ 金字塔增加了一个分辨率参数，不改变算法选择，所以没有按第 7 节开多方案试验；三档均由用户指定。

环境、数据、索引与 `NAVIT-20261111-1-edge-loading-01` 相同：Ubuntu 24.04.5 虚拟机，8 vCPU / 9.7 GiB，Qt 6.4.2，Release，offscreen；湖北 PBF（SHA256 `da2b0200…0297ab`），`xyz-v4-labels2`。显示器为 2560×1440，缩放 1（`~/.config/monitors.xml`）。

## 方法

临时程序 `ClarityBench`（存档为 `evidence/ClarityBench.cpp.txt`，测完已从 CMake 删除）。武汉中心 114.305,30.593，1280×800，层级 z13/z15/z17。每档每层 3 次：先删除 PNG 得到冷缓存，从 request 计时到完成帧；然后同实例再请求一次，作为热帧。另外统计生成的 PNG 数量与体积，并用 `/usr/bin/time -v` 记录进程峰值 RSS。

- 冷生成耗时：中约为低的 1.36×，高约为低的 1.63–1.75×。
- 热帧：三档都在 10–15 ms。
- 磁盘缓存：中约为低的 1.7×，高约为低的 2.5×。
- 清晰度：截图 `evidence/crop-low-z15.png` 与 `evidence/crop-high-z15.png` 显示，高档的文字与建筑边线明显更锐利，字号相同。没有做定量清晰度指标。

## 与 Navit 的比较

| 项 | 结论 | 依据 |
| --- | --- | --- |
| 清晰度档位 | 不适用 | Navit 0.5.7 不使用栅格瓦片金字塔，直接按屏幕分辨率绘制矢量 displaylist，没有对应的“瓦片渲染密度”参数（核查依据：所装版本的 `navit.xml` / layout 中无此类配置） |
