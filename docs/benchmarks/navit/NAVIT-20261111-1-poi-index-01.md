# NAVIT-20261111-1-poi-index-01

日期：2026-11-11（Asia/Shanghai）。负责人：1（跨模块；POI 数据主责 2）。关联决策：`DEC-20261111-1-poi-index-01`。状态：**部分完成**。本组 A/B/C 已实测并选 B；Navit 同任务耗时受阻，未测。

## 范围

地图右上角的搜索：按名称找兴趣点，展示离起点最近的 20 个。索引在首次搜索时建立。入选组合：

- A：SQLite FTS5 trigram（写入导入缓存，不足 3 字退回扫描）
- B：内存单字倒排（每个进程首次搜索时建立）
- C：SQLite R 树，由近及远扩圈

三者共用同一结果语义：`QString::contains` 不区分大小写，按大圆距离排序，距离相同时按 id；共用参考实现 `searchNearestPoisByScan`。

## 环境与数据

Ubuntu 24.04.5 虚拟机，8 vCPU / 9.7 GiB，Qt 6.4.2，GCC 13.3.0，SQLite 3.45.1（libsqlite3-0 3.45.1-1ubuntu2.9），Release。数据为湖北 PBF（SHA256 `da2b0200…0297ab`）导入缓存：36,875 个 POI，其中 18,669 个有名称。每个组合使用缓存文件的独立副本，因为 A/C 会写入索引表。

## 方法

临时程序 `PoiBench`（存档为 `evidence/PoiBench.cpp.txt`，测完已删除）。起点为武汉中心 30.593,114.305。先测首次搜索（建索引）的耗时与缓存文件增量；再对 12 个查询各重复 20 次，记录中位数/P95，与全表扫描逐 id 比对；峰值 RSS 用 `/usr/bin/time -v` 测得。

## 与 Navit 的比较

| 项 | 结论 | 依据 |
| --- | --- | --- |
| 名称子串 + 最近 20 个 | 部分对应 | Navit 0.5.7 内置 GUI 有地址/名称搜索，以及地图点周边 POI 菜单（`navit.xml` 的 “Map Point” 菜单）。按名称子串取离起点最近的 N 个，没有在所装版本中核实到完全相同的功能 |
| 同名临近 POI 合并 | 未核实 | 没有核实 Navit 0.5.7 maptool 是否对同名临近 POI 去重；本机 binfile 中对应要素未逐一检查 |
| 搜索耗时 | 受阻未测 | 本机 Navit 只有 GTK/internal GUI，没有可脚本化的搜索计时入口 |

补测：从源码构建 Navit，在 `search_list_get_result` 前后计时，对同一 binfile（maptool 已生成）执行相同查询。负责人：1，需与 2 号协作。
