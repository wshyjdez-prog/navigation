# NAVIT-20261102-2-osmx-import-01

日期：2026-11-02（Asia/Shanghai）。负责人：2。状态：**受阻（未测）**。

## 范围与基线

本轮交付 2 号“统一数据”：OSMX v1 解析库 `p1_data_osmx`、导入页面 `.osmx` 支持（`p1_import_page`/`OsmxImportAdapter`）、本地缓存清单与共享 `OsmxStore`，以及格式/存储/接口文档。未实现 A*、HMM、LinuxRenderer、主窗口装配或语音；这些能力不计入本报告。

- 本组基线：`main`（`e3ec3c0`）+ 本轮未提交修改（分支 `codex/member-2/osmx-unified-data`）。
- 本轮环境：Windows 11 开发主机，Qt 6.11.0 / MinGW GCC 13.1.0，Debug；仅用于编译、单元测试和页面冒烟，**不是**统一 Ubuntu 虚拟机，不作为验收或性能依据。
- Navit：共同基线尚未建立，本机未安装 Navit，无版本/配置/插件校验值，也未核查其导入与加载能力的精确定义（见 [规范第 1 节](../../navit-benchmark.md#1-已确认要求与当前状态)）。

## 任务映射与可比性

2 号在 [对标规范](../../navit-benchmark.md) 中的等价任务是“同源地图准备与加载、等价查询、包加载/更新恢复”。本轮仅覆盖其中：

1. 从 OSMX 文件准备内存路网（解析 + 校验 + 索引）；
2. 首次加载/缓存写入；
3. 基础查询（节点/道路/标签/关联/出边/最近节点/视野内道路）。

Navit 侧的对应能力须在其实际版本中核查：其地图准备通常由 maptool 生成 binfile，运行时加载 binfile 并查询。双方**输入格式与预处理边界不同**，且本轮没有同源 OSM 输入（只有 OSMX 样例，来源路径与生成参数不完整），因此尚不具备“同源、同区域、同规模”的可比条件，不计算任何差值或倍数。

## 正确性（非性能结论）

- `p1-osmx-tests`：19 个用例，18 通过 / 0 失败 / 1 跳过；跳过项是需 `P1_OSMX_REAL_FILE` 的真实文件用例，设置后单独执行通过（2.7 s）。覆盖合成路网、9 类损坏文件、进度/取消、缓存、Store。
- 新增 `p1-import-page-tests`（CTest `import-page-osmx`）：2 用例通过——真实页面后台导入合成 `.osmx`（缓存 + `OsmxStore` 快照 + 拓扑），以及模拟重启后从缓存重新打开同一数据集。
- 真实 `test.osmx`：49,356,479 B，SHA-256 `a9c4d90b…6467`；912,730 节点、121,964 道路、1,658 关系、44,986 可导航道路、536,688 有向边、16,408.873 km 可导航几何长度。与独立 Python 解析逐项核对一致（节点/道路/关系/边界/标签计数）。
- `ImportPage + MainWindow` 冒烟：页面以固定 ID `import` 注册、后台导入、缓存落盘、`OsmxStore` 活动数据集、页面状态恢复均通过；仅验证本模块路径，使用本地 stub 替代 libosmium。
