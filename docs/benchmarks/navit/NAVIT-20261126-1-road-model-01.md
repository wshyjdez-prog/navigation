# NAVIT-20261126-1-road-model-01

日期：2026-11-26（Asia/Shanghai）。负责人：1（跨模块；路网建模主责 3，数据契约 2，规划调用 4）。关联决策：`DEC-20261126-1-road-model-01`（试验 A/B，最终选 A）。对标状态：**部分**。本组修改前后与两种候选已在同一虚拟机上实测；Navit 本机未安装，同口径建图与规划耗时受阻未测。

## 范围

把 `NavigationWorkflow` 里自写的路网建模改用开源实现。数据导入模块不变。

| 部分 | 旧实现（6b2fc50） | 正式方案 A |
| --- | --- | --- |
| 投影 | 自写等距圆柱 | Boost.Geometry srs 横轴墨卡托（`+proj=tmerc +ellps=WGS84`，原点为路网中心） |
| 边长 | 导入时的长度 | Boost.Geometry haversine（R=6371008.8 m，与导入长度一致） |
| 图 | 每次查询重建 `adjacency_list` | 每个路网建一次 `compressed_sparse_row_graph`；行车模式用 `filtered_graph` 视图 |
| 搜索 | `astar_search`，h=0 | `astar_search`，以地表直线距离为下界 |
| 吸附 | 一般模式用网格最近节点（节点不可用即报错）；行车模式线性扫描 | Boost.Geometry R*-tree 最近邻，按模式和方向过滤（起点需出边，终点需入边） |

## 环境与数据

见 `evidence/environment.txt`：Ubuntu 24.04.5，8 vCPU（宿主 i7-13620H），9.7 GiB；GCC 13.3.0、CMake 3.28.3、Qt 6.4.2、Boost 1.83.0；Release。试验期另装了 GeographicLib 2.3（仅候选 B 使用，已清理）。数据为本机湖北导入缓存，sqlite SHA256 `05b67d42f80733661a191bb7d91bc451470f45a9a8de37ecf06c75b56b939025`。中心点为武昌 30.5530,114.3200。

## 方法

- 组件测试（`evidence/RoadModelBench.cpp.txt`）：区域半径 1/3/5/10 km。建网预热 1 次、正式 5 次。查询为 200 对随机点（种子 20261126），计时含吸附与路线。旧实现按改动前代码等价复刻，每次查询都生成行车子图。正确性：一般模式下，每条成功路线与同图上的穷举 h=0 A* 比较代价。
- 端到端测试（`evidence/WorkflowBench.cpp.txt`）：通过 `NavigationWorkflow` 先加载起点 1 km，再规划，与地图操作相同。8 条跨城路线（53–406 km）+ 20 对城区路线，两种模式，每组 3 次。基线为 `6b2fc50` Release，编译同一文件。
- 统计：中位数与 P95（最近秩）；峰值内存用 `/usr/bin/time -v`。按 旧/基线 → A → B 的顺序依次运行，无其他负载。清理后再用正式代码复测 A（`evidence/post-*`）。
- 复现：`p1-roadmodel-bench <cache.sqlite> <legacy|A|B> 1 3 5 10`；`p1-workflow-bench <cache.sqlite> 3`；`python3 -I summarize.py evidence/workflow-baseline.csv evidence/post-workflow-A.csv`。测试程序已从项目移除，复测时把 `.cpp.txt` 复制回去并按决策记录第 3 节加回 CMake 目标。

端到端时间主要花在 2 号的区域读取（SQLite）上；当起终点超出已加载区域，或需要分级路网时，每次规划都要重建路网。A 的搜索更快，但被更贵的建网抵消，所以端到端与基线持平或略慢。在起终点都已在加载区域内的常见交互中，不需要重建，只剩吸附和搜索，A 明显更快（组件结果）。

候选 B（GeographicLib）的结果保留在决策记录中：查询约为 A 的 3 倍时间，建网约 2.5 倍，端到端慢 30–50%。

## 与 Navit 的比较

| 项 | 结论 | 依据 / 原因 |
| --- | --- | --- |
| 对应能力 | 对应（部分） | Navit 的 `route_graph_build` 按 `route_depth` 从 binfile 取路段建图，再用 `route_path_new` 搜索；起终点吸附到最近路段。本组是“区域读取 + 建模 + 吸附 + A*”。数据结构不同，任务等价 |
| 建图 / 规划耗时 | 受阻未测 | 本虚拟机未安装 Navit（`environment.txt`）；以往报告中的 Navit 0.5.7 也没有可脚本化的规划计时入口 |
| 质量 | 不计算 | 没有 Navit 同起终点的路线 |

补测（负责人 1，需 3、4 号协作）：从源码构建 Navit 0.5.7，在 `route_graph_build` / `route_path_new` 前后加计时（或走 dbus），用 maptool 生成同源 binfile。对本报告的 8 条跨城路线和 20 对城区路线，比较建图与规划耗时、路线长度。

## 限制与下一步

- 建网成本上升。可考虑：缓存最近一次的路网模型，或者在加载区域时预留更大的余量，减少规划时重建。是否做由 3、4 号评审决定。
- 边长使用球面 haversine，与导入长度口径一致；相对 WGS84 椭球约有 0.04% 差（候选 B 实测）。
- 虚拟机结果，不推广到物理硬件。
