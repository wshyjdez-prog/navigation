## 范围与基线

本轮为第二次作业 4 号"对接真实计算和导航事件"的对接层交付：`AsyncPlannerBridge`（QThread+Worker 线程化对接桥）、`StubRoutePlanner`（确定性规划桩）、`RecordingController`（验证桩）及 7 例集成测试与演示程序。未新增或优化路径规划、地图匹配算法本身——3 号真实 A*/HMM 交付前，规划计算由 stub 以固定延迟模拟，不存在可与 Navit 比较的真实规划性能。

- 本组基线：`main`（`cb056d0`）+ 本轮对接层提交（分支 `codex/member-4/assignment2-integration`）。
- 本轮验证环境：统一虚拟机 p1-linux-member4，Ubuntu 24.04.4 LTS amd64、G++ 13.3.0、Qt 6.4.2、CMake 3.28.3、Ninja、Debug、-j2。实测：configure 0 / build 0 / 警告 0；全量 CTest **9/9**（新增 navigation-integration 7 例、navigation-planner-demo）。构建与测试串行运行，未采样后台负载，不具备性能比较条件。
- Navit：未建立共同基线；本虚拟机未安装 Navit（沿用 [1 号受阻报告](NAVIT-20261101-1-integration-shell-01.md)的核查结论），无精确版本、插件/配置校验值及能力等价结论。

## 环境、任务与正确性

按 [对标规范](../../navit-benchmark.md) 第 2 节，4 号模块拟核查的等价任务是"同定位输入的更新、引导、偏航触发至新路线可用"。本轮对接层只覆盖其中的**规划请求下发与结果回流链路**；偏航触发、重算去重策略的状态机实现属第 3 次作业，尚无可观测的端到端偏航场景，与 Navit 无等价任务可言。

本轮只做正确性验证（结果不属于 Navit 对标）：链路端到端 7 例全过——回流线程归属（Qt::QueuedConnection）、规划期间主线程心跳（400ms 模拟计算期间 >=3 次心跳，UI 循环不阻塞）、stop() 取消在途后零回调、故障注入下陈旧 requestId 拒绝、桥析构静默、stub 输出确定性。演示程序 300ms 模拟计算实测主线程心跳 4 次、路线 `stub-route-1` 100.08 m。
