## 页面工厂交接约定

继续使用 `MainWindow::registerPage(id, title, description, page)`，不增加业务专用的入口耦合。

- 稳定 ID：`import`、`map`、`algorithms`、`offline`、`history`、`components`、`settings`。
- QWidget 必须在 GUI 线程创建、注册。返回 `true` 后堆栈取得所有权；返回 `false` 时所有权保持原状，调用方按实际归属处理，不能删除其他路由已持有的页面。
- 一份 QWidget 只对应一个页面 ID；拒绝重复挂到其他 ID、将已有页面的内部控件当成页面、或将主窗口/堆栈当成页面。拒绝时旧页面与当前路由保持不变。
- 替换当前页时保持当前 ID；替换后台页时不切换当前页。旧页面先移出堆栈，随后 `deleteLater()`；新页按 Qt 父子关系随窗口销毁。
- 同 ID、同指针重新注册只更新标题、说明与导航提示，不重复加入堆栈或销毁页面。
- 页面首次成功注册后才启用入口。主题切换更新已有控件，不重建页面或重置业务输入。

下面是接入形状，`createAlgorithmPage` 为交接占位名称，当前仓库没有该工厂；不是可直接编译的真实调用：

```cpp
auto* page = createAlgorithmPage(services, theme); // 由 3 号提供
if (!window.registerPage("algorithms", "算法实验", "路径规划与轨迹匹配", page)) {
    page->deleteLater(); // 仅限本例刚创建、尚未交出所有权的页面
}
```

各模块提供自己的 CMake 目标、公开工厂头文件及依赖清单，1 号在应用装配处创建服务并注入工厂。主窗口不直接访问数据库、私有算法模型或渲染器内部状态。后台计算使用 Qt 排队信号等方式回到 GUI 线程；取消、退出及迟到结果处理由模块服务实现并验证。目标间若出现循环依赖，由 1 号抽取公共 UI/契约目标后再接入，不把业务实现塞进 MainWindow。
