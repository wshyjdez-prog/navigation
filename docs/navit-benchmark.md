## 2. 各模块的测试安排

下表是要核查的任务与指标建议，**不表示 Navit 已提供对应能力，也不是已测结果**。每个功能子模块都应明确映射和适用指标，不能以一份整机启动报告代替其他模块比较。

| 负责人/范围 | 待核查的等价任务 | 适用指标建议 |
| --- | --- | --- |
| 1：框架、用户页面、发布 | 启动至可交互、页面操作、离线启动 | 冷/热启动耗时、操作延迟、峰值 RSS、CPU、分发体积 |
| 1：LinuxVoiceAdapter | 同文本/语言的播报、同音频指令的处理及回调 | 首次发声延迟、总耗时、回调延迟、吞吐量、内存、识别/播报质量；各子能力分别核查 |
| 2：导入、StorageAdapter、离线包 | 同源地图准备与加载、等价查询、包加载/更新恢复 | 导入/预处理耗时、加载延迟、查询 P50/P95、吞吐量、峰值内存、磁盘体积与恢复正确性 |
| 3：路径规划、地图匹配、异步计算 | 同路网/车辆约束/起终点规划、同轨迹定位到道路 | 规划/匹配 P50/P95、峰值内存、吞吐量、取消响应、路线合法性/成本与匹配误差；不可假定 Navit 内部使用 A*/HMM |
| 4：定位、状态机、偏航重算、回放 | 同定位输入的更新、引导、偏航触发至新路线可用 | 定位/引导延迟、重算耗时、重复请求数、触发正确性、CPU/内存；区分判定等待与计算耗时 |
| 5：LinuxRenderer、地图、仪表盘 | 同区域/视野/缩放/内容密度的地图、路线/标记及平移缩放 | 帧耗时 P50/P95、FPS、输入至画面更新延迟、峰值内存、CPU/GPU（可测时）与视觉完整性 |

Navit 是否支持某项任务、能否在相同计时边界观测，须在实际版本中核查并附配置、文档/源码位置或运行证据。没有对应接口时可比较等价用户任务，但必须标清整流程与模块内部计时的区别；无法等价的指标写“不适用+依据”。

## 3. 比较与统计口径

1. 先登记本组代码基线和 Navit 精确版本、来源、配置/插件、构建模式、各自依赖。1 号维护共同基线，模块报告引用基线及其校验信息；变化时保留旧记录，新增基线并重测。
2. 在同一统一 Linux 虚拟机内分开运行，记录宿主 CPU/内存、虚拟 CPU/内存、磁盘、图形加速/驱动、显示协议/分辨率、音频/定位后端及后台负载。模拟与真实服务分开，双方实际使用的后端差异须披露。
3. 使用同源、同区域/版本/规模的数据、同起终点/轨迹/操作序列和功能约束，记录校验值、坐标系/单位、转换命令/参数及差异。准备、转换、索引或预加载开销单列，端到端总成本也须说明。
4. 先列正确性/质量标准、通过/总数、误差与失败，再比较资源和时延。不能用缺少道路限制、更少绘制内容、较低语音质量或未完成任务换取“更快”的结论。内部算法不同本身不妨碍等价任务比较。
5. 事先固定计时起止事件、工具/脚本版本、预热次数、正式重复次数、缓存冷热、超时阈值、运行次序及统计方法。双方一致地记录逐次数据、样本数、中位数、P95、峰值 RSS（MiB）及适用吞吐量。长时间场景注明时长、采样频率及独立运行数；样本少时说明分位数不稳定，不伪造缺失指标。
6. 失败和超时列入总次数并单列，耗时分位数注明是否仅统计成功样本。不同成功率/质量的结果不能仅凭成功样本的时延判断整体优劣。
7. 每项列单位及优劣方向。差值为 `本组值 − Navit 值`；相对变化为 `(本组值 − Navit 值) / Navit 值 × 100%`，保留正负号。耗时/内存通常越低越好、FPS/吞吐量通常越高越好；质量项单独解释。Navit 值为零、未测、不适用或不可比时不计算比例/倍数。
8. 不设未经确认的“超过 Navit 才通过”阈值。比较落后、超时、不可比均须保留；优化后重测相关场景，记录本组修改前后及与 Navit 的差距。复用旧 Navit 数据需证明版本、配置、输入、环境及方法一致。
